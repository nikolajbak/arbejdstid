# Redesign af Arbejdstid — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ny brugerflade (stil C, kundens farve) med tre faner, start/stop i centrum, Fortsæt-felter, skift med ét tryk, vælgerark med opret, valgfri opgave, ingen zoom og ingen standard-opgavetyper.

**Architecture:** `app.js` (836 linjer) deles i moduler pr. skærm, der deler tilstand via `tilstand.js`. Rene beregninger (Fortsæt, farver, skift) lægges i `core.js` og testes. Kundefarver styres med `data-farve` på elementer og CSS-variabler, så lys/mørk håndteres i CSS.

**Tech Stack:** Vanilla JS-moduler, CSS (color-mix), Firebase 13 (uændret), `node --test`, Firestore-emulatoren.

**Spec:** `docs/superpowers/specs/2026-10-08-redesign-design.md`

## Global Constraints

- Intet byggetrin; ingen nye afhængigheder.
- Farvenøgler og hex præcis som specens tabel; rækkefølge `skov, ler, indigo, blomme, rosa, okker, hav, skifer`.
- Tekst i UI på dansk, præcis som specen angiver ("Start ny", "Intet ur kører", "Fortsæt", "I dag", "+ Tilføj tid", "Hvad lavede du?", "Gem uden opgave", "Gemte {kunde} · {t:mm}", "Uden opgave", "Vælg en kunde", "Skriv en timepris", "Ingen tid registreret i perioden.", "Beløb er ekskl. moms.").
- Tom opgave = `opgavetypeId: ''` (aldrig null/undefined i data).
- Ingen tekst under 12 px; felter ≥ 16 px; knapper/rækker ≥ 44 px høje.
- DOM bygges kun med `h()` (tekstnoder, aldrig innerHTML).
- `npm test` og `npm run test:regler` skal bestå efter hver opgave.
- Browsertest kun mod emulatorerne (`npm run emulatorer`, `python3 -m http.server 8000`).

## Review Focus

1. Ur kører og brugeren trykker et Fortsæt-felt med samme kombination som det kørende → det må ikke vises (udelukkes af `senesteKombinationer`), og skift må aldrig miste det kørende urs tid.
2. Kunde eller opgavetype arkiveret/slettet, men brugt i registreringer og i det kørende ur → Fortsæt springer dem over, lister viser "(slettet)"/navn uden at gå i stykker, farve falder tilbage til `farveFor`.
3. Vælgerarket: søgetekst med store/små bogstaver og mellemrum ("  acme ") må ikke tilbyde "Opret" for en eksisterende kunde.
4. Stop-arket lukkes ved tryk udenfor → uret kører videre uændret (intet gemt to gange).
5. Gamle data: kunder uden `farve`, registreringer/ur med `opgavetypeId` fra før (ikke-tom) og backup-filer fra før redesignet skal stadig kunne læses og vises.

### Task 1: Rene funktioner og data i core.js, store.js og konto.js

**Files:** Modify `core.js`, `store.js`, `konto.js`, `tests/core.test.js`, `tests/store.test.js`

**Interfaces:**
- Produces (core.js):
  - `FARVER: string[]` (8 nøgler i specens rækkefølge)
  - `farveFor(kunde) -> string` — `kunde.farve` hvis i `FARVER`, ellers `FARVER[hash(id) % 8]` (hash: sum af tegnkoder).
  - `naesteFarve(kunder) -> string` — færrest blandt ikke-arkiverede; lighed → første i `FARVER`.
  - `senesteKombinationer(registreringer, kunder, opgavetyper, ur, antal = 4) -> [{ kundeId, opgavetypeId }]`
  - `skiftUr(tilstand, ny: { kundeId, opgavetypeId }, nu: string ISO, timepris: number, id: string) -> tilstand` (ren; ny registrering får `id`, `note: ur.note ?? ''`)
  - `UDEN_OPGAVE = 'Uden opgave'`
- `summarize`: type `''` → navn `UDEN_OPGAVE`, sorteres sidst i `typer`.
- `toCSV`: tom opgavetype → tomt felt.
- `validateBackup`: kunde `farve` valgfri tekst; registrering/ur `opgavetypeId` må være `''`.
- store.js `defaultData()` → `opgavetyper: []`. konto.js `sikrProfil` opretter ikke opgavetyper.

- [ ] **Step 1: Tests** i `tests/core.test.js`:

```js

test('naesteFarve vælger den mindst brugte, første ved lighed')

test('skiftUr gemmer det kørende ur og starter det nye')

  → registreringer får { id:'r9', kundeId:'a', opgavetypeId:'', start, slut: nu, timepris: 800, note:'n' }, ur = { kundeId:'b', opgavetypeId:'t', start: nu, note:'' }

test('toCSV giver tomt felt for tom opgave')
test('validateBackup accepterer farve og tom opgave')
```
