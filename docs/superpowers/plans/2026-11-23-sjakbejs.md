# Sjakbejs og løn til teamet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** En sjakbejs pr. team, timeløn pr. medlem, udbetalinger og en lønoversigt, der viser, hvad hver har til gode.

**Architecture:** Ren beregning i `core.js` (løn ved dato, lønoversigt, dækningsbidrag). `sjakbejs` og `loen` på teamdokumentet; udbetalinger i ny samling `teams/{id}/udbetalinger`, synket via `sky.js` som de øvrige samlinger, men kun for teams. Ny DOM-fil `loen.js` med kortet og arkene.

**Tech Stack:** Vanilla JS-moduler, Firebase Firestore, `node --test`, `@firebase/rules-unit-testing`.

**Spec:** `docs/superpowers/specs/2026-11-23-sjakbejs-design.md`

## Global Constraints

- Dansk i brugerflade, filnavne og funktionsnavne; hver ny fil starter med en kommentar om, hvad den er.
- Ingen nye afhængigheder. Ny `.js`-fil skal i `FILER` i `sw.js`.
- Kun godkendte registreringer/poster (uden `afventer`) tæller.
- Mig (`brugere/{uid}`) får ingen `udbetalinger`; der må ikke lyttes på en samling, reglerne ikke tillader.

## Review Focus

- Medlem uden timeløn: optjent 0 kr, timerne vises som »uden løn«; ingen NaN. → test i Task 1.
- Lønændring midt i perioden: tid før `fra` bruger den gamle løn. → test i Task 1.
- Tidligere medlem med åbent beløb vises stadig; tidligere medlem i nul vises ikke. → test i Task 1.
- Sjakbejs fjernet fra teamet: et andet medlem kan udpege ny. → regeltest i Task 2.
- Medlem, der ikke er sjakbejs, forsøger at ændre `loen` eller skrive en udbetaling: afvises. → regeltest i Task 2.

### Task 1: Beregning i core.js

**Files:** Modify `core.js`; Test `tests/core.test.js`

**Interfaces — Produces:**
- `loenVed(loen, uid, dag: 'YYYY-MM-DD') → number | null` — seneste trin med `fra <= dag`.
- `loenOversigt(team, registreringer, poster, udbetalinger) → [{ person, ms, msUdenLoen, optjent, udlaeg, kontant, udbetalt, tilGode }]` — medlemmer i `team.medlemmer`-rækkefølge, derefter tidligere personer med |tilGode| ≥ 0,005. Filtrerer selv afventende fra. `ms` er rundet tid (`dagsTider`).
- `daekningsbidrag(kundeId, registreringer, team, kunder) → { tidKr, loen, bidrag, msUdenLoen }`.
- `saetLoen(loen, uid, fra, kr) → loen` — ny kopi; erstatter trin med samme `fra`, sorteret efter `fra`; `kr === null` fjerner trinnet.

- [ ] Tests: `loenVed` (før første trin → null, mellem trin, på `fra`-dagen); `loenOversigt` med 1 t 10 min (rundes til 1,25 t) × 200 = 250, + udgift 100 + brændstof 50 − kontant 30 − udbetaling 200 = 170; afventende registrering tæller ikke; lønskift 2026-11-10 fra 200 til 250; medlem uden løn → `msUdenLoen` > 0, optjent 0; tidligere medlem i nul udelades; `daekningsbidrag` 2 t à 500 med løn 200 → 600; `saetLoen` erstatter/fjerner.
- [ ] `npm test` fejler, implementér, `npm test` grøn. Commit.

### Task 2: Regler

**Files:** Modify `firestore.rules`; Test `tests/regler/regler.test.js`

- [ ] `gyldigtTeam`: tillad valgfri `sjakbejs` (string eller null) og `loen` (map).
- [ ] Medlemsopdatering: må også ændre `sjakbejs` og `loen`, når

- [ ] Tests: udpeg uden sjakbejs ✓; ikke-sjakbejs skifter eksisterende ✗; sjakbejs giver videre ✓; ny sjakbejs ikke medlem ✗; sjakbejs fjernet → andet medlem udpeger ✓; kun sjakbejs ændrer `loen`; udbetaling af ikke-sjakbejs ✗, af sjakbejs ✓, ugyldigt beløb ✗, medlem kan læse ✓.
